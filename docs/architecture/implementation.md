# Catalog 架构迁移

目标：日常内容改动只修改一个工具文件，公开站点不依赖数据库或站内登录，保留当前视觉和已有 URL。

- [x] 核对完整数据库与现有快照；保留当前公开目录、编辑内容和 SEO。
- [x] 建立 `content/tools/*.json` 唯一内容源、集中分类、校验及可重复生成流程。
- [x] 建立 `features/catalog` 的公开类型、查询、服务端读取和浏览器索引边界。
- [x] 列表首屏最多发送 24 张卡片，交互时按需获取索引；详情不进入列表数据。
- [x] 投稿入口迁移到公开 GitHub Issue / 可配置外部表单，准备人工接受后生成内容 PR 的工作流。
- [x] 退役站内登录、后台审核、邮件和请求写库；旧入口明确跳转或返回 Gone。
- [x] 更新维护文档、自动检查；10 项测试、类型及格式检查、完整生产构建和页面验证通过。

本地生产验证覆盖首屏静态卡片、2,518 条详情 URL 的站点地图、旧链接跳转、退役 API、索引缓存和工具 OG 图片；浏览器验证覆盖搜索、分页、分享链接和公开投稿入口。

保留历史 SQL 和数据库本身。首次迁移只完成本地重构；后续按用户要求发布 GitHub 投稿入口与重构代码，并配置投稿标签及创建内容 PR 的权限。远程数据库不做删除。
